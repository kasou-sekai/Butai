# Butai implementation and security audit — 2026-08-12

## Follow-up full-project audit — 2026-08-21

- Fixed literal placeholder text shown when creating or deleting an empty preset.
- Configuration load failures now put the app into read-only recovery mode, preventing a corrupt or newer configuration from being overwritten by an empty runtime configuration.
- A primary configuration using a newer schema is no longer silently downgraded to an older backup.
- Window matching now requires a bundle identity before a window can be accepted, preventing title-only rules from moving an unrelated application's window.
- Match-rule weights are bounded and regular expressions use a conservative, bounded subset to prevent integer overflow and catastrophic backtracking from edited configuration files.
- Runtime URL execution now enforces the same HTTP(S)-only policy as the settings UI.
- Saved application paths are checked against their bundle identifiers and adapter allowlists before launch.
- Non-finite layout and timeout values fail to safe defaults instead of reaching AppKit, Accessibility APIs, or deadline calculations.
- Empty workspace arrays recover to one usable workspace instead of leaving the UI and navigation model in an invalid state.
- The overlay popup is clamped vertically and scrolls horizontally when all Spaces do not fit on screen.
- Packaging now uses a unique temporary build directory by default and removes only that validated directory on exit, avoiding predictable shared `/private/tmp` build paths.
- Removed unused persisted placeholders for Caps Lock shortcuts, switch actions, feedback duration, horizontal overlay position, workspace shortcut indexes, and the unused `SpaceChangeOrigin` type. Historical JSON keys remain harmlessly decodable as unknown fields.
- Expanded the core suite from 12 to 16 tests; Debug tests and a warnings-as-errors Release build pass.

## Deferred after 0.4.4 experiments

- `open -na` does not reliably foreground the ChatGPT/Codex menu bar when invoked from another Space, and does not itself create a usable window.
- The follow-up `Command-N` experiment depends on foreground focus and is therefore not reliable across Spaces.
- Forced Codex new-window support is intentionally shelved. Current behavior safely starts or activates Codex with `reusePreferred` and makes no new-window guarantee.

## Fixed in 0.4.2

- Finder capture no longer depends solely on `AXDocument`. A bounded JXA query reads each Finder window's target URL and correlates it with the Core Graphics window ID.
- Finder metadata queries and all adapter subprocesses now have hard timeouts and forced termination fallback.
- After Butai creates a Finder window, its new window ID is accepted as a safe fallback even if Finder metadata is temporarily unavailable.
- Preset capture is asynchronous so Finder metadata lookup does not freeze the settings UI.

## Fixed in 0.4.1

- Finder folder paths are normalized before matching, including `file://` URLs, percent encoding, and trailing slashes.
- Finder new-window automation creates the window first and then assigns its target folder.
- Newly created windows are identified by their Core Graphics window ID before falling back to existing matches.
- Legacy `.folder` preset items migrate to the Finder adapter automatically.
- The unified ChatGPT/Codex app (`com.openai.codex`) is preferred; legacy `com.openai.chat` presets migrate automatically.
- Configuration saves are serialized so an older asynchronous write cannot overwrite a newer edit.
- Configuration and backup files use mode `0600`; their directory uses `0700`.
- Configuration reads are limited to 10 MiB and reject non-regular files.
- Title regex rules fail closed when invalid or oversized.
- Core Graphics window bounds are type-checked instead of force-cast.
- Temporarily enabled Mission Control symbolic hotkeys are restored to the user's previous setting.

## Known functional gaps

- Caps Lock shortcuts and shortcut event swallowing are not implemented. Placeholder settings were removed so the persisted model no longer implies support.
- Only the first preset for each workspace is editable; multiple scenes are represented in the model but not exposed in the UI.
- Preset import/export, general schema migration, diagnostic export, and user-facing cancellation are not implemented.
- Shell command preset items are intentionally not executable and have no creation UI.
- Generic-app “new window” requests are not implemented; application presets normally reuse or activate the app.
- Exact multi-window web-page/tab restoration is not implemented. Edge only uses an accessible current URL as a window-level signal.
- ChatGPT/Codex remains experimental: launch/activate and layout restore are supported, but a specific conversation or reliable additional window is not.
- Finder/VS Code/Edge automation does not yet have a per-application AX timeout; an unresponsive accessibility server can delay work on the main actor.
- Split View, Stage Manager, simultaneous multi-display navigation, and more than nine regular Spaces are unsupported. Full-screen application Spaces are detected and navigable, but remain dependent on private topology data and adjacent system shortcuts.
- Calibration traversal, switch-direction feedback, login-at-startup, automatic updates, crash reporting, and full English localization are not implemented.
- Accessibility labels and keyboard navigation are partial rather than comprehensively audited with VoiceOver.

## Remaining release and security risks

- Test packages are ad-hoc signed. There is no Developer ID signature, hardened runtime, notarization, or update signature verification, so this is not a production distribution channel.
- The application is not sandboxed and stores user-selected paths and window metadata locally. No data is uploaded, but security-scoped bookmarks are not implemented.
- Space discovery and navigation use private SkyLight/CGS interfaces. OS updates can break them, and this design is unsuitable for Mac App Store distribution.
- Accessibility and Apple Events permissions are powerful. Finder automation is limited to a fixed script plus an argv path, and process launching uses argument arrays rather than shell interpolation.
- Browser URLs and window titles can be sensitive. Butai currently has no telemetry or diagnostic upload; any future logging/export must redact paths, titles, and URL query data.
